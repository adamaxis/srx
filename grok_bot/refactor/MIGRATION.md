## Load order
`init.lua` loads tables → targeting → anim → actions → movement → heartbeat. Modules share names through `registry.lua`, so they can be loaded in any order, but the shared names are only resolved at call time.

## API compatibility
`require("actor.init")` returns the same `ActorAI` table, and `ActorAI.heartbeat(context)` keeps its signature. Check: it loads under lua5.4 with a stub `game` and gives `type(heartbeat) == "function"`. All 8 files pass `luac -p`. The only free global left is `game`, as before; `states` is now bound explicitly in actions.lua.

## Renames applied
`ActorServiceFlag.{active,targets_world_actors,action_candidate_reserved,effect_locked}` → `ActorStatus.{ACTIVE,AI_RUNNER,DOWN,DEAD}`; `ActorSpawnFlag.{transitioning,effect_route}` → `ActorFlag.{PEDESTRIAN,QUEST}`; `ActorBehaviorFlag.{action_window_open,high_effect}` → `BehaviorFlag.{IN_BAND,ESCORT}`; `EntityKind.*` → `SpriteType.*`. **The numeric values do not change**, so behaviour is unchanged. Only the names change, and they follow our ROM docs.

## Risks
- [H] The renames assume the repo's spawn/service flags are the ROM fields +0x9E / +0x10 / +0xB0. The values match, but the host should confirm it fills them from those fields.
- Calls between modules now go through the registry, which adds a small per-call cost. Upvalues captured at load time stay nil if a module reads them before init finishes, so read registry names inside functions.
- Line ranges are tied to the current upstream revision. Rerun the split script after any upstream change.

## Equivalence testing (done for synthetic states)
From the repository root: `LUA_PATH="grok_bot/refactor/?.lua;;" lua5.4 grok_bot/tests/equiv_heartbeat.lua [trials] [seed] [frames]`

**How it works**
- Loads the original repo `actor_ai.lua` and `actor.init` side by side. Each gets its own stub `game`.
- Drives 3 persistent actors per trial for 120 frames. Behaviour and render phases alternate, and 25% of the fields are re-rolled each frame.
- Uses every profile id in the source, plus dynamic-encounter ids.
- Mock services return deterministic, hash-based results with the shapes the code expects; 1 call in 7 returns a random shape on purpose.
- Each call compares five things, serialized:
  1. the return value or the normalised error
  2. the mutated context
  3. the whole `game.actors` state
  4. the full log of service calls and their arguments
  5. the call order
- **Result:** 36,000 calls (seed 21) and 4,800 calls (seed 5) gave **0 mismatches**. The run is deterministic.

1. Integrate `grok_bot/refactor/tools/heartbeat_recorder.lua` under `gameplay/scripts/tools/` only if the active project does not already provide the recorder.
2. Copy `out/heartbeat_record_hook.hpp` next to `field_scene_runtime.cpp` and apply the patch: `cd qt_runtime/src/field && patch -p1 < out/field_scene_runtime.record.patch`. The patch adds:

   - Fallback if `call_string` cannot reach the module [H: module discovery is outside the srx repo]: add `return require("heartbeat_recorder").wrap(ActorAI, os.getenv("SRX_HEARTBEAT_RECORD"))` as the last line of actor_ai.lua instead of `return ActorAI`.
4. Replay: `LUA_PATH="refactor/?.lua;refactor/tools/?.lua;;" lua5.4 tests/replay_heartbeat.lua /tmp/play.rec`. It reports:
   - mismatches of the original and of the split against the recording (return values, every actor state, context after the call)
   - any service-call divergence: a different call name, argument or order from what was recorded

**Each record holds:** the context (function fields replaced by their recorded results), all of `game.actors` before and after, every `game.movement.*` / `game.modules.{combat,entity_motion,items,magic}.*` call with its arguments and returns, and the result or error.

## Function-level equivalence (tests/equiv_units.lua)
**How it works**
- The original's local functions are found through `debug.getupvalue` on `ActorAI.heartbeat`; the split's come from `actor.registry`.
- All 57 shared functions are called with the same random state (105 state fields) and context, plus shaped generators for:
  - dynamic target actions
  - item and spell dispatch and casts
  - pending spell effects
  - received hits
  - projectile records (primary/secondary, stopped/terminal, burst timer)
  - collision codes and probes
- Each call compares the return values, state, context, `game.actors`, the extra arguments and the service log.
- Error text is normalised (file:line and local-variable names), because the `lib.int68k` parameter is named `v` where the original used `value`. That difference only appears with invalid table inputs.

**Results**
- 0 mismatches over 8,550 calls (seed 3, 150 per function).
- Line coverage from this test alone: actions 63%, anim 61%, movement 52%. Before, the heartbeat-level test reached actions 31%, anim 42%, movement 46%.
- `tests/mutants.sh` now runs both tests. **All 8 planted mutants are caught.** The two Collision.BLOCKED mutants that earlier looked equivalent are caught by the `movement_collision_code` / `probe_movement` argument generators.
