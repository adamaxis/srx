# Ghidra conversion project

This is the active C++/Qt project for behavior recovered from the canonical
ROM and Ghidra export. The parent `decompilation/` directory is the shared
source-data and research root; its top-level native-port sources are historical
and inactive:

- Build this project from its own CMake files and presets. The parent native
  project is not an entry point for current work.
- This project has no dependency on `GenesisBus`, ROM-addressed RAM, VDP
  objects, or the legacy `shadowrun_port` library.
- Its functions use ordinary typed values and fixed-size host containers.
- Source addresses are provenance comments, not runtime lookup keys.

The first slice covers the controller edge expression at `0x195C`, the 64-word
palette operations at `0x1088`/`0x10D6`/`0x1368`, the seventeen-pass
transitions at `0x131C`/`0x12F6`, and the title state shared by `0x1A9E`,
`0x1BAC`, `0x1BEA`, `0x1C1E`, `0x1C6A`, `0x1E4E`, `0x2634`, and `0x26D0`. The
`0x1A9E` source-order frame coordinator now composes those typed leaf states;
the Qt host consumes its logo-column, sprite-projection, circuit-phase,
prompt, copyright, controller, and termination requests. Vblank waits,
resource setup, and unresolved hardware calls remain explicit boundaries until
their source inputs are understood.

Build this directory when validating the conversion slice. Its presets write
to the repository-level `build/conversion/workbench/{debug,release}` and
`build/conversion/qt/{debug,release}` directories. The target prefix remains
`shadowrun_ghidra_*`.

The domain ownership and source/test layout are documented in
[`../WORKSPACE.md`](../WORKSPACE.md) and
[`../docs/ghidra-conversion-source-layout.md`](../docs/ghidra-conversion-source-layout.md).

When using VS Code, open the repository-level `shadowrun.code-workspace` file.
Its CMake Tools source directory, build/test tasks, and launch configurations
point only to this Ghidra project.

For Visual Studio 2022, open `decompilation/ghidra_conversion/` directly as a
CMake project. Do not select the historical parent native-port project.

```text
C:/msys64/ucrt64/bin/cmake.exe --preset ghidra-conversion-debug
C:/msys64/ucrt64/bin/cmake.exe --build --preset ghidra-conversion-debug
C:/msys64/ucrt64/bin/ctest.exe --preset ghidra-conversion-debug
```

Run those commands from decompilation/ghidra_conversion. The release variants
are ghidra-conversion-release in each command. To build every conversion test
executable instead of only the workbench runner, use
ghidra-conversion-debug-all or ghidra-conversion-release-all as the build
preset.

The `shadowrun_ghidra_conversion_runtime` target is the conversion-side
composition runtime. Its source files live under `src/integration/`; it links
the reviewed domain modules and is consumed by the standalone runner. It is
not the native game runtime and it is not an emulator.

The standalone conversion runner can be built and run with:

```text
C:/msys64/ucrt64/bin/cmake.exe --build --preset ghidra-conversion-debug
../../build/conversion/workbench/debug/shadowrun_ghidra_conversion_runner.exe --assets ../assets
```

The conversion runtime also exposes
`integration::bootstrap_field_session()`. It composes the manually traced
post-menu field-entry slice (`0x007F0..0x0094C`) from the existing typed audio,
entity, world-effect, scene-entry, resource, and render contracts, including
the sixteen-slot `0x0A8EA` behavior-frame service, its source-verified
`0x0AB02` transition-completion callee, and the source-verified `0x0ACAE`
field-service action router. Its downstream camera, action,
movement, effect, continuation, and presentation boundaries remain
explicit callbacks; it does not silently turn missing conversion work into a
playable-runtime shortcut.

The startup/session record files are regenerated by the separate offline
extractor when the canonical ROM or the asset directory changes:

```text
../../build/conversion/workbench/debug/shadowrun_ghidra_startup_record_extract.exe \
  ../input/shadowrun_genesis_us.bin ../assets
```

It writes only the three named source-record files under
`assets/records/startup/`; it is not part of the Qt runtime and is not run by
CTest or an ordinary game launch.

This runner is a conversion-workbench startup probe, not the native game and
not an emulator. It loads the direct-asset alias table, verifies the boot/title
asset set, composes the typed `0x0236 -> 0x073A -> 0x5D746` startup ordering,
and reports the source-derived vblank, sprite, scroll, and resource-stream
counts. Its resource, transfer, palette, audio, and sprite-record callbacks
are explicit conversion boundaries; a `title_ready` result means the parent
control flow and asset requirements were exercised, not that the native port
is playable or that those child systems have been source-verified.

## Standalone map and entity viewer

The independent Qt authoring app is in
[`tools/map_entity_viewer/`](tools/map_entity_viewer/). Its source, Python
requirements, build launcher, and README are kept together. Run `build.cmd`
there to create `dist/shadowrun_map_entity_viewer.exe`; it loads the shared
`../assets/` maps and writes annotation data under `../gameplay/world/`.
Building or running the viewer does not require the game executable.

## Qt conversion frontend

The runnable Qt host for the converted code is built from `qt_runtime/`. Its
build directories are `../../build/conversion/qt/debug/` and
`../../build/conversion/qt/release/`, and its runtime dependencies are
`shadowrun_ghidra_conversion_runtime` and Qt Widgets.

The live binary is the build-directory root copy, for example
`../../build/conversion/qt/release/shadowrun_ghidra_conversion_qt.exe`.
Close that process before rebuilding; Windows will not overwrite a running
exe. Do not launch `qt_runtime/shadowrun_ghidra_conversion_qt.exe`.

The `ghidra-conversion-qt-release` configure, build, and workflow presets
target `shadowrun_ghidra_conversion_qt.exe` at the Qt Release build-directory
root. Close the running executable before rebuilding.

The production executable `shadowrun_ghidra_conversion_qt.exe` accepts `--assets`
and `--help`, then opens the game window. Screenshot, smoke, and behavior-check
commands belong to the separate `shadowrun_ghidra_conversion_qt_qa.exe` runner.
Build the separate Debug application from this directory:

```text
C:/msys64/ucrt64/bin/cmake.exe --preset ghidra-conversion-qt-debug
C:/msys64/ucrt64/bin/cmake.exe --build --preset ghidra-conversion-qt-debug
../../build/conversion/qt/debug/shadowrun_ghidra_conversion_qt.exe --assets ../assets
# Directly exercise the converted field-entry bridge without opening a window.
../../build/conversion/qt/debug/shadowrun_ghidra_conversion_qt_qa.exe --field-smoke --assets ../assets
# Write the source-sized field frame for visual inspection.
../../build/conversion/qt/debug/shadowrun_ghidra_conversion_qt_qa.exe --field-dump field.bmp --assets ../assets
# Write a pre-title frame at a specific converted source-frame boundary.
../../build/conversion/qt/debug/shadowrun_ghidra_conversion_qt_qa.exe --boot-dump-frame 200 boot-200.bmp --assets ../assets
```

Release:

```text
C:/msys64/ucrt64/bin/cmake.exe --preset ghidra-conversion-qt-release
C:/msys64/ucrt64/bin/cmake.exe --build --preset ghidra-conversion-qt-release
../../build/conversion/qt/release/shadowrun_ghidra_conversion_qt.exe --assets ../assets
```

The full Qt QA suite is built and run separately. CTest launches the QA
commands and component checks without showing the game window. The test preset
stays quiet when everything passes and prints the failing test output when it
does not:

```text
C:/msys64/ucrt64/bin/cmake.exe --build --preset ghidra-conversion-qt-release-tests
C:/msys64/ucrt64/bin/ctest.exe --quiet --preset ghidra-conversion-qt-release-tests
```

Use the matching `ghidra-conversion-qt-debug-tests` presets for a Debug run.

The window starts from the converted boot/title integration, presents the
direct title assets through the converted `0x1A9E` frame coordinator, and
routes startup-menu input through the converted New Game/Load Game/Joshua menu
contracts. On the New Game path, `field_ready` now invokes the separate
`qt_runtime/src/field/field_scene_runtime.cpp` composition adapter. That adapter
feeds the extracted action/mode/profile/descriptor/collision/event/terrain
records into the converted field-session bootstrap and paints the direct
field map/HUD assets. The startup scene is scene `2`, so the adapter selects
`field.maps.mode.2` and the matching `records.field.scenes.scene.02.*` source
records. A loaded save selects its restored `FFDDC4` scene id through the same
typed scene-resource table instead of rejecting every non-2 save or silently
substituting row 0. The Qt field bridge now also accepts held arrow keys as the source D-pad nibble,
loads the extracted `0x19D2` heading table and `0x0C002` movement vectors,
and drives the converted heading-slew, terrain-probe, directional-probe, and
movement-step functions. A right-input smoke pass advances the selected
Joshua record by the extracted `(+40,0)` vector. This is still not a claim
that the complete field behavior is source-verified: the converted terrain
object bounds and aligned route descriptors are now connected, while event
transitions and walking animation records remain explicit conversion
boundaries.

The Qt callbacks remain explicit presentation/source boundaries; they do not
replace unresolved source behavior with code from the inactive native-port
tree. Dynamic
runner records, event-driven field transitions, walking animation, and
save-slot restoration are still incomplete conversion boundaries.
`--field-smoke` loads the direct catalog, runs the converted field bootstrap,
and paints one 320x224 host frame without writing an artifact. `--field-dump`
uses the same path but writes that 320x224 frame. `--boot-dump-frame` advances
the source pre-title loop to the requested VBlank boundary and writes the
composed Sega/guy/lightning/FASA frame without entering the Qt event loop.
`--field-smoke-move-right` additionally submits one held right D-pad sample
and reports the resulting typed field position. These smoke commands are
deliberately not registered as CTest tests.

Before the startup menu is entered, the conversion integration now loads the
ROM-derived startup records and runs the converted `0x59318` save-roster seed.
New Game then publishes the selected `0x42B0` Joshua record into conversion
state before the field-session bootstrap. Reaching the field screen now proves
that the direct source records and common `0x007F0..0x0094C` entry sequence
were accepted; it does not claim that movement, dynamic runner records, or
the complete field renderer are source-verified yet.

When a callback cannot yet be grounded in the canonical ROM/Ghidra export, it
must remain an explicit reported boundary. Treat an apparently missing field,
resource, or behavior as evidence of an incomplete conversion sweep and
re-audit the source before inventing a replacement routine.

The source-understanding layer is organized by game subsystem under
`include/shadowrun_ghidra/<domain>/`, `src/<domain>/`, and `tests/<domain>/`.
See [`../docs/ghidra-conversion-source-layout.md`](../docs/ghidra-conversion-source-layout.md)
for the domain boundaries and the rule for adding or consolidating files.
