# B3 outside-function range triage

## Scope and result

This triages the B3b byte-reachability snapshot for US ROM SHA-256 `92a614491fc3ea12a6df32459cce08b48574b7b814e244c07eb860dc5c6edb7e`: 171 reported intervals / 33,576 bytes. `[C] code` and `[C] data` classify the ROM bytes and control-flow evidence only; they do not claim that the port reproduces gameplay. No headless numeric comparison was made for these ranges, so no behavior is called ROM-correct.

[C] 170 intervals (33,574 bytes) are executable instructions or instruction continuations. [C] The remaining 2-byte interval at `0x166514..0x166515` is ASCII text reached by a false indirect-dispatch candidate, not a routine. [H] Whether any runtime record can ever select that text pointer through the indirect `0x054960` site remains unbounded; keep that call unresolved. The analyzer report still lists the conservative candidate so this document can audit the original 171-range set.

Ranges are byte spans after subtracting known function extents; a row is not necessarily a whole routine. Starts at `0x00285C`, `0x00AE58`, and `0x013E30` overlap the tail of an instruction whose opcode begins before the span, so those are extent-boundary fragments rather than standalone entry points.
